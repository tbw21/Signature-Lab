# Copy and scope: scoped security review

This is a reviewed presentation change, not an independent organizational audit.

- The inherited verifier compares supplied signed transactions with deterministic references.
  It is not a firmware scanner or a watermark-search tool. The new introduction identifies
  the published Dark Skippy example, not all possible variants. The main result explicitly
  says that a match does not rule out seed leakage or other firmware attacks.
- The removed master-key/no-passphrase line is only explanatory. The fingerprint binding,
  cached root, QR and account derivation stay intact. The existing technical FAQ now tells
  operators to use the test words without an additional passphrase.
- No runtime JavaScript, vendor byte, source assembler, CSP, permission, network request,
  storage operation, camera lifecycle, reference policy or metadata condition changed.
- Template projection tests reverse the expressly authorized copy changes and compare the
  complete page to the original byte hash. CSS projection does the same for intended styling.
- One paragraph, ordinary wrapping, existing gold tone, minimum original text sizes and a
  forced-colour fallback are required. Do not hide a scope limit to force one-line layout.
- All 22 Help IDs, titles and categories remain; there is no second table of contents or
  optional-module dependency in the test flow.
- A brand name, matching fingerprint, screenshot or earlier software pass does not attest
  hardware origin. Prior user-reported operations stay assigned to their original release.

Remaining external gates: actual phone/desktop and physical signer/optical acceptance,
normal opening modes and browser engines where unavailable, authenticated publisher
signing and inherited dependency provenance, independent external review/reproduction.
No revised detection-rate claim, safety certificate, authenticated firmware profile,
stealth claim or allegation about Foundation/SeedSigner/COLDCARD is made.
