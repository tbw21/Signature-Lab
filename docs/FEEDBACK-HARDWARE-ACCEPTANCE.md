# Feedback refinement — actual-device/browser acceptance addendum

Use the exact frozen versioned HTML and the full retained hardware checklist. All wallets
must be disposable and never funded. No real seed, bypassed safeguards or broadcast.

1. Record release hashes, device and exact firmware, OS/browser and downloaded-file/HTTPS
   opening mode. Check the demo from Wallet and Help: visible dialog, two valid signatures,
   no reference match, no active wallet change or session increment. Reopen after scrolling
   its details: the result must be visible. Test Close and Escape where available.
2. New test wallet must be easy to find beside 12/24 words. Fresh unused same-length/new-length
   changes work; after confirming/loading/signing, New and changed length ask before clearing.
   Keep/Escape must preserve exact words, fingerprint, current result and session. Confirm
   requires loading the new wallet on the actual signer. Test both word lengths.
3. Save current result and session record from the confirmation. Check downloaded bytes and
   identity externally; a click alone is not proof. Block a download in a disposable browser
   test profile: the failure must remain visible inside confirmation with no discarded data.
4. End a 2- or 3-case session, before and after a result. The active banner disappears from
   Test/Advanced; Session retains exact plan, events, completed/not-completed counts and export.
   A mismatch, file-review or failed capture remains flagged after ending. Normal operator
   end is not labelled a failed signature. Complete plans require explicit ending as before.
5. Check next-session route in Advanced, single New control, QR alignment/pixels, large text,
   keyboard focus, native font rendering, screen rotation, permission changes and page restore.
   No stale reset, scan or signing operation resumes itself. Retain evidence before advancing.

This checklist is not a record of execution. Physical signers/real optics here: none. Any
blocker requiring different bytes produces a new candidate and full restarted acceptance.
No new support or attack-detection percentage follows from these interface changes.
