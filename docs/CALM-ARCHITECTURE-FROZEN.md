# Calm workspace stabilization contract

Scope frozen 2026-09-17, before new stabilization implementation. Target: 0.16.1-rc1.

## Recovery and authoritative release
The mounted deliverables contain v0.15.2-rc1's complete standalone source package and the
later 0.16.0-rc1 zen-work/dev-2.html preview. The subsequent calm-work source/test files
are not present (only screenshots). Recover the preview's changes into that source
assembly; do not substitute v0.12.2 or assert that the lost test checkpoint was recovered.
Record hashes, preserve all provided artifacts. 0.16.0 preview is not a qualified release.
Only release.json supplies runtime version identity. Publish one uniquely versioned
candidate with a detached manifest; no updater or second active-release controller.

## Requirements and acceptance
R1: Three equally sized, legibly labelled Test / Advanced / Session controls at mobile
widths 320, 360, 390, 438, 768; consistent selected state, keyboard focus and min 44px
primary navigation targets. Reflow 200% text and text spacing without clipped content.
R2: Beginner signing view exposes current identity, essential amounts, QR/transport,
all-output read-only review and response actions. Advanced/session are separate spaces.
No second verifier or state source. Preserve every optional capability already present.
R3: Each output's amount, full address, script, order and role projects the same prepared
public transaction; all 20 outputs supported. Invalid/preparing data never shows stale QR
or a stale destination list. Unavailable output review blocks the signing presentation.
R4: Recognized returned-file cleanup/default policy details remain available in technical
details/FAQ, while unexpected fields, mismatches, incomplete checks and historical
unresolved findings are visible. Custom policy/PSBT/editor state stays apparent.
R5: Save result uses the single existing evidence exporter where available; summary fallback
explicitly remains a summary. No seed/private key/root serialization. Export names short,
content-derived, safe; data retains provenance. Naming is not a stealth mitigation.
R6: Navigation, disclosure, unit or QR-format changes cannot mutate wallet, transaction,
policy, completed result or history; asynchronous focus must not target a departed view.
No camera start as side effect. Existing camera stop/reacquisition/deadline policy unchanged.
R7: Preserve core cryptography, metadata admission policy, QR codecs and camera controller
byte-for-byte. Test scope remains BIP84 P2WPKH ECDSA disposable/fake transactions only.
R8: Complete retained regression and updated equivalent UI assertions, independent
crypto/structure/replay checks, fault and upgrade/adoption/rollback/idempotence simulations.
No counting discarded development runs, fixtures or physical user reports as new passes.
R9: Freeze HTML/archive and SHA256 before acceptance. Run from clean extraction; rebuild
and repack exactly. Any acceptance blocker disqualifies candidate, never patch frozen bytes.

## Module and authority boundaries
Trusted core: existing Bitcoin/signature verifier, metadata framing/policy and prepared
transaction, result/evidence snapshot and current session journal. No changed crypto.
Presentation: page/CSS, application view methods, pure read-only prepared-output projection.
Optional: guided planner, alternate QR transport, evidence downloads, advanced controls.
Display failures must not fabricate success or auto-modify core state. Downloads cannot
mutate verification. History is a projection from TbwSessionJournal, not new ledger.
One JSON filename/export boundary; no extra timer, retry engine or camera controller.
All changes require a reason, traceability entry and regression coverage.

## Privilege and ownership
Single local browser document; no services, installation, Bitcoin/Fulcrum access, wallets,
network API, persistent store or background daemon. Retain original offline CSP and all
vendor bytes; no external assets, remote fonts, telemetry or code downloads. Camera is
operator-initiated, audio false, stopped on completion/navigation/hide as existing policy.
Publisher signing keys remain operator-owned and are not created or requested here.
Public evidence contains untrusted device data; review before sharing. Only disposable
seeds; never fund addresses, broadcast or weaken a signer protection.

## Lifetime, resume, recovery, upgrade and rollback
Private state in current tab only. Page reload/crash creates a fresh test; no persistent
seed/crash resume. Back-forward restoration retains memory where browser permits but
never acquires camera or advances automatically. View navigation preserves authoritative
state; explicit new wallet resets it. Save evidence before advancing/reloading. Upgrade:
close old page, open new frozen file and fresh wallet. Rollback: close new page, open
untouched prior release and fresh wallet; do not migrate in-memory signing state.
Guided failures remain terminal until explicit end. No retry of unknown signing outcome.
Existing bounded invalid camera-observation admission remains unchanged.

## Retired paths
Narrow unbordered mobile utility links; default wall of technical panels; editor-only output
review; verbose UUID-bearing report filenames; summary-only primary Save; uncancelled
workspace-focus tasks. No runtime fallback to retired code. Prior files remain audit fixtures.

## Qualification boundaries
Actual physical camera/SS/CCQ firmware, OS power loss, real full disks/mounted read-only
media and user-comprehension testing are separate gates. Simulated event/fault injection
is not physical evidence. Node installation/storage/boot tests are not applicable. Test
normal file/http origins and available engines without bypassing system policy. Record
all unavailable paths. No safety percentage, 100% reliability or firmware certification.
