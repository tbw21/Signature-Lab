# How to deliver this build

## Controlled testing now
Provide one handoff ZIP. Keep one versioned HTML as the runnable entry, plus its exact source
archive, qualification report, full test results, checksum manifest, acceptance evidence,
short change notes and hardware checklist. START-HERE explains the order. Do not mix old
candidates into the top-level handoff. Extract to a new local folder; verify hashes before use.
The SHA-256 manifest detects byte differences; it is unsigned and is not publisher authentication.
Do not request a real seed. Save test evidence before switching versions or closing.

## Public delivery later
First complete the declared real device/browser/opening-mode matrix, dependency provenance,
independent review/rebuild, Foundation investigation as applicable, and user-comprehension
acceptance. TBW owns the release-signing key and publication account; neither is created here.
Publish immutable versioned assets with externally verifiable signed hashes. Keep one active
release pointer; keep older releases as an explicit archive, not competing main downloads.
A hosted edition needs acceptance of that actual deployment, delivered bytes and configuration;
local-file checks do not qualify a website. Do not insert tracking, third-party scripts, a
service worker or automatic updates into the tested HTML as a publishing convenience.
If application bytes or build inputs change, make a new candidate and restart qualification.
A detached signature/acceptance record may be added without modifying frozen HTML/source.

## Recovery
Stop distributing a blocked release and restore a previously accepted one only if such an
accepted release exists; otherwise withdraw the download. Preserve incident evidence. Publish
clear status, unique versions and a verification path. This handoff does not grant deployment
permission or assert the external gates have passed.
