## Requirements and acceptance
F01: The optional demo clearly states it checks a recorded transaction, not malware execution
or the user's signer. One click reveals the existing computed result, with valid signature
and reference-comparison findings separated. Reopening brings its result into view. Missing
or failed modal/check never reports success or mutates wallet/result/journal/camera state.
F02: Ended guided status appears only in Session, with completed/requested counts, not an
active case number. Active/halted/complete-but-not-ended controls remain reachable. End
never deletes history/evidence or clears a failure. Existing journal owns all transitions.
F03: One New test wallet control on Step1 uses the existing randomizeAll transition. No
second reset in Advanced. Same-length regeneration is retained. Word-length changes and
that control use one request/confirmation wrapper; a used/acknowledged wallet, history,
current artifact, diagnosis or plan requires explicit confirmation. Fresh unused changes
may remain immediate. Cancel/Escape/missing confirmation leave state unchanged. A pending
confirmation cannot act on changed wallet/result/journal/input state, execute twice or
bypass guided locks. An active camera is never hidden or restarted by this operation.
F04: The confirmation offers the existing current-result/session export operations before
replacement; it never claims download success. Failed export is visible inside the dialog.
No seed is newly included in exports. Existing evidence ownership is unchanged.
F05: An ended plan in Advanced offers a clear route to the wallet/record rather than an
empty setup dead end. Session retains prior file-review, incomplete, control/capture findings.
Display-only counts are derived from the single journal; normal operator end is neutral.
F06: Preserve QR pixels, fingerprint, all-output review, result scopes, native typography,
stationary navigation, mobile reflow, enlargement, accessibility/keyboard/forced colors,
and the existing finite-import/camera/reference-self-check/security regression requirements.

## Architecture, privileges, state and contracts
One Fv coordinator, prepared test, immutable result, TbwSessionJournal, reference gate and
camera owner remain. Only coordinator, template/CSS and tests/docs may change. No dependency,
network permission, persistent state, firmware profile, new script family or decoder change.
Existing inspect/plan/apply/verify/status/rollback contracts remain. The wallet confirmation
is transient UI intent, bound to existing state/revision identities; only randomizeAll applies
a replacement. Demo uses only runDemonstration/Up; no demo seed loader or second verifier.
Files build under current user privileges; release tools retain atomic no-overwrite behavior.
One uniquely versioned handoff/application is the release pointer; historical archives stay.

## Resume, rollback, recovery and upgrades
State stays in the tab. Reload requires a fresh wallet; no secret persistence or auto-resume.
End preserves records; cancel does not undo physical signing. Navigation cannot resume a
failed scan. Page restoration cannot apply an old replacement confirmation. Missing optional
demo UI leaves normal tests usable. Failure to present destructive confirmation fails closed.
No automatic retries. Operator may explicitly try again. Close older version after saving
needed evidence; fresh context adoption/upgrade/rollback simulations retained. OS installation,
bootloader, recovery boot, Bitcoin/Fulcrum services and data migrations are not applicable.

## Retired UI

unconfirmed UI replacement of a used wallet; singular 'file reviews'; counting ordinary end
as a fault tone. Their underlying checks/history/reset operations are not retired.
