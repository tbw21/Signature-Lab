# Wallet card physical acceptance addendum
Use the unchanged candidate identified by the external HTML/source hashes and retained full
checklist (docs/HARDWARE-ACCEPTANCE.md plus reference/clarity addenda). This is not a pass record.

1. Record exact candidate hash, actual browser/OS/opening mode, signer model/firmware and operator.
2. Generate a fresh disposable wallet; test 12 and 24 words. Never overwrite a funded wallet,
   enter real wallet words, fund generated addresses, broadcast or disable signer safeguards.
3. Scan or enter the words without a passphrase. Compare the fingerprint in the combined card
   against the actual signer. Enlargement must change size only, not words/fingerprint or test.
4. Check normal/enlarged/reduced QR at actual phone and desktop sizes, including large text.
   No text overlaps, clipping, obscured code, accidental acknowledgement or unexpected navigation.
5. Confirm Test wallet loaded advances only by explicit activation. Enlarge never acknowledges.
6. Exercise all workspaces, modal example, transaction/output review, return scan/import, warning
   result and evidence export on the same original transaction. Keep original responses.
7. Re-run real permission denial, locks/backgrounding/recovery and long QR cases. Browser
   simulations do not replace optical tests. Save each result before advancing.

Any blocking failure disqualifies the candidate. Fix in a new version and restart applicable
qualification. Publisher signing, provenance, independent review and original Foundation
investigations remain open; a matching session is not firmware certification.
